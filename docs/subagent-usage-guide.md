# 하위 에이전트(Subagent) 사용 가이드

## 핵심 원칙

> **"기본은 직접, 위임은 명시적 요청 시에만"**

에이전트는 모든 작업을 **현재 세션에서 직접 수행**하는 것을 기본으로 한다.
하위 에이전트(서브에이전트)는 사용자가 **명시적으로 위임을 요청**하거나, 작업의 성격상 병렬 처리가 필수적인 경우에만 생성한다.

---

## 왜 이 원칙이 필요한가?

### 서브에이전트의 비용

| 항목 | 비용 |
|------|------|
| 서브에이전트 1개 기반 비용 | 25-35K 토큰 (시스템 프롬프트 + 컨텍스트 로드) |
| invite-tester 풀 루프 | 200-400K+ 토큰 |
| 단순 파일 조회 위임 | 15-20K 토큰 (직접 수행 시 1-2K) |

### 서브에이전트의 문제점

1. **토큰 낭비**: 직접 하면 1분 걸릴 작업에 25K+ 토큰 오버헤드 발생
2. **컨텍스트 손실**: 현재 세션의 맥락이 서브에이전트에 온전히 전달되지 않음
3. **응답 지연**: 서브에이전트 생성·실행·결과 수집 과정에서 불필요한 지연
4. **디버깅 어려움**: 서브에이전트 내부 오류가 상위로 전파될 때 맥락 추적 곤란

## 기본 동작 변경 대상 (9개 스킬)

아래 스킬들은 원래 서브에이전트를 자동 생성하도록 설계되었으나,
**기본 동작을 현재 세션 직접 수행으로 변경**한다.

| # | 스킬 | 원래 동작 | 변경 후 동작 |
|---|------|----------|-------------|
| 1 | `invite-tester` | 개발자·테스터 서브에이전트 2개 자동 생성 | 사용자가 명시적으로 "서브에이전트로" 요청 시에만 생성 |
| 2 | `understand` | 리서치 서브에이전트 자동 위임 | 현재 세션에서 직접 코드베이스 분석 |
| 3 | `understand-chat` | 리서치 서브에이전트 위임 | 현재 세션에서 직접 질의 응답 |
| 4 | `understand-explain` | 리서치 서브에이전트 위임 | 현재 세션에서 직접 설명 |
| 5 | `understand-diff` | 리서치 서브에이전트 위임 | 현재 세션에서 직접 diff 분석 |
| 6 | `writing-plans` | 플래닝 서브에이전트 위임 | 현재 세션에서 직접 계획 수립 |
| 7 | `executing-plans` | 구현 서브에이전트 위임 | 현재 세션에서 직접 실행 |
| 8 | `subagent-driven-development` | 다수 서브에이전트 병렬 생성 | 사용자가 "병렬로" 요청 시에만 생성 |
| 9 | `dispatching-parallel-agents` | 병렬 서브에이전트 자동 디스패치 | 사용자가 명시적으로 요청 시에만 |

## 서브에이전트 사용이 적합한 경우

서브에이전트는 다음 조건을 **모두** 충족할 때만 생성한다:

1. **사용자가 명시적으로 요청** — "서브에이전트로", "병렬로", "나눠서 처리"
2. **작업이 독립적** — 공유 상태나 순차 의존성이 없는 2개 이상의 작업
3. **작업 규모가 충분** — 서브에이전트 오버헤드(25K+ 토큰)를 상쇄할 만큼 큰 작업
4. **컨텍스트 전달이 자명** — 서브에이전트에 별도 설명 없이 작업 범위를 전달 가능

### 적합한 사용 예시

- ✅ 사용자가 "invite-tester로 개발-검수 루프 돌려줘"라고 요청
- ✅ 3개 이상의 독립 모듈을 동시에 구현해야 하는 대규모 작업
- ✅ 코드베이스 전체 감사처럼 오래 걸리는 리서치 작업

### 부적합한 사용 예시

- ❌ 파일 1-2개 읽고 요약하는 단순 작업
- ❌ 순차적으로 진행해야 하는 의존성 있는 작업
- ❌ 현재 세션의 컨텍스트가 중요한 디버깅 작업
- ❌ 사용자가 위임을 요청하지 않은 일반 작업

---

## 요약

```
IF 사용자가 명시적으로 위임 요청
  AND 작업이 독립적·대규모
  → 서브에이전트 생성
ELSE
  → 현재 세션에서 직접 수행
```
