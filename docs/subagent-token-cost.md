# 하위 에이전트 토큰 비용 분석

## 1. 비용 구조

### 서브에이전트 기반 비용

서브에이전트 1개를 생성할 때마다 발생하는 **고정 오버헤드**:

| 항목 | 토큰 수 | 비고 |
|------|---------|------|
| 시스템 프롬프트 로드 | 8-12K | 에이전트 기본 설정 + 도구 스키마 |
| 스킬 목록 로드 | 10-15K | 활성 스킬 전체 목록 주입 |
| 사용자 규칙 로드 | 5-8K | 전역 규칙 + 프로젝트 규칙 |
| 작업 컨텍스트 전달 | 2-5K | 부모 → 자식 지시 사항 |
| **합계** | **25-35K** | **서브에이전트 1개당 최소 비용** |

### 스킬별 비용 추정

| 스킬 | 서브에이전트 수 | 예상 비용 | 비고 |
|------|---------------|----------|------|
| `invite-tester` (풀 루프) | 2개 + 3라운드 | 200-400K+ | 가장 비용이 큰 스킬 |
| `understand` | 1개 | 50-100K | 코드베이스 규모에 비례 |
| `dispatching-parallel-agents` | 2-5개 | 100-250K | 병렬 작업 수에 비례 |
| `subagent-driven-development` | 3-8개 | 150-400K | 태스크 수에 비례 |
| 단순 리서치 위임 | 1개 | 30-50K | 직접 하면 5-10K |

## 2. 비용 대비 효과 판단 기준

### 서브에이전트가 효과적인 경우 ✅

| 조건 | 이유 |
|------|------|
| 독립 작업이 3개 이상 | 병렬 처리로 **벽시계 시간** 절약 |
| 단일 작업이 100K+ 토큰 규모 | 컨텍스트 분리로 정확도 향상 |
| 교차 검증이 필수 | invite-tester의 편향 제거 가치 > 토큰 비용 |
| 장시간 백그라운드 리서치 | 메인 세션 차단 방지 |

### 서브에이전트가 비효율적인 경우 ❌

| 조건 | 이유 |
|------|------|
| 파일 1-3개 읽고 답하는 작업 | 25K 오버헤드 vs 직접 2-3K |
| 순차 의존성 있는 작업 | 병렬화 불가, 오버헤드만 추가 |
| 현재 대화 맥락이 핵심인 작업 | 컨텍스트 전달 손실 위험 |
| 코드 1-2군데 수정 | 직접 하면 30초, 위임하면 2분+ |

## 3. 토큰 절약 팁 5가지

### 팁 1: 기본은 직접 수행

```
직접 수행 비용:     5-10K 토큰
서브에이전트 위임:  30-50K 토큰 (6-10배)
```

단순 작업은 무조건 직접 수행한다. 서브에이전트는 **복잡하고 독립적인 대규모 작업**에만 예약한다.

### 팁 2: invite-tester는 핵심 기능에만

invite-tester 풀 루프(200-400K+)는 **결함이 치명적인 핵심 기능**에만 사용한다.
단순 UI 수정이나 텍스트 변경에는 직접 검증이 더 효율적이다.

### 팁 3: 리서치 서브에이전트 최소화

"코드베이스에서 X를 찾아줘" 같은 작업은 `grep`, `find`, `read_file`로 직접 수행한다.
리서치 서브에이전트는 **전체 아키텍처 분석** 같은 대규모 탐색에만 활용한다.

### 팁 4: 서브에이전트에 명확한 범위 전달

서브에이전트 생성 시 "이 파일들만 봐라", "이 함수만 수정해라"처럼 **범위를 최소화**하여
불필요한 탐색 토큰을 줄인다.

### 팁 5: 병렬보다 순차가 싼 경우를 인식

2개 작업이 각각 10K 토큰이면:
- 순차 직접 수행: 20K 토큰
- 병렬 서브에이전트: 20K + 50K(오버헤드) = 70K 토큰

**시간 절약이 3.5배 비용 증가를 정당화할 때만** 병렬화한다.

## 4. 결론

> **서브에이전트는 도구이지 기본값이 아니다.**
> 토큰 예산을 의식하고, 직접 수행이 가능한 작업은 직접 한다.
> 위임은 사용자의 명시적 요청 또는 명백한 병렬화 이점이 있을 때만 한다.
