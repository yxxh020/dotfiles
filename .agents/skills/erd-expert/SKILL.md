# 실제 테이블 기반 ERD 생성

## 작업 범위 확인

- 프로젝트 지침과 관련 이슈를 먼저 확인하고 결과물의 실제 열람 경로를 기록한다.
- 설계 제안, 로컬 DB 변경, 운영 DB 변경을 구분한다. 사용자가 승인한 환경과 작업 범위에서만 실행한다.
- 이미 작성된 생성기·조회 서비스·ERD 문서를 찾아 원본을 개선한다. 같은 목적의 별도 구현을 추가하지 않는다.
- 문서에 원하는 설계를 적는 것과 실제 테이블·화면이 전환된 것은 별개다. 진행 중인 작업은 완료라고 보고하지 않는다.

## 원본과 관계 확인

1. ORM 스키마, 적용된 마이그레이션과 DB 카탈로그를 대조한다. 차이가 있으면 어느 환경의 어떤 상태를 도식화하는지 명시한다.
2. 모든 테이블·컬럼·기본키·외래키·고유 제약·널 허용·자료형을 확인한다. 코드에만 존재하는 관계를 실제 외래키처럼 표시하지 않는다.
3. 역할별 화면이 읽는 데이터와 원본 테이블의 대응을 작성한다. 과정·회차·참여자 같은 공통 원본을 역할별로 중복 생성하지 않는다. 역할별 뷰·집계는 공통 원본과 연결한다.
4. 신규 기본키가 정수 정책인 프로젝트에서는 `INT IDENTITY` 또는 해당 DB의 동등한 자동 증가 정수를 사용한다. 기존 키 변경은 참조 이관 계획을 별도로 마련한다.
5. 공통 코드는 프로젝트의 확정 명칭을 따른다. `codes`가 지정되었다면 다른 이름으로 바꾸지 않는다. 그룹·코드 조합의 유일성과 참조 제약을 보장하여 다른 그룹의 코드를 잘못 참조하지 않게 한다.
6. 반복되는 상태·유형·검수 값은 공통 코드로 연결한다. 코드명, 표시명, 정렬, 활성 상태를 구분하고 실제 참조와 화면 라벨의 일치를 확인한다.

## 데이터 이관과 조회

- 기존 목업·JSON·컴포넌트 인라인 업무 데이터를 목록화하고 정규화된 테이블에 연결한다. 반복 항목과 관계를 하나의 JSON 컬럼에 통째로 넣어 정규화를 우회하지 않는다.
- 승인된 이관 입력은 시드 전용 자원으로 둘 수 있다. 화면과 조회 서비스가 그 자원을 런타임에 가져오지 않게 한다.
- 원천마다 같은 짧은 ID가 다른 대상을 가리킬 수 있다. 원천 구분과 키 매핑을 보존하고 이름이나 ID가 같다는 이유로 자동 병합하지 않는다.
- 이관은 참조 순서, 중복 실행, 누락·고아 행, 건수와 값의 일치로 검증한다. 운영 시드나 배포 시 자동 시드를 임의로 실행하지 않는다.
- 화면과 ERD 행 데이터는 인증된 서버 조회를 거쳐 실제 테이블에서만 가져온다. 내장 배열, 정적 JSON, 임의 생성 행, 목업 및 브라우저 저장소를 조회 실패 대체 데이터로 쓰지 않는다.
- 빈 테이블은 빈 상태로, DB 실패는 오류와 재시도로 표시한다. 다른 테이블의 첫 행이나 예제 행으로 대체하지 않는다. 사용자 요청이 없다면 "샘플"·"Mock" 안내는 붙이지 않는다.
- 조회 API는 테이블 허용 목록, 컬럼 선택, 행 수 제한과 매개변수 검증을 적용한다. 입력 문자열을 SQL 식별자로 직접 이어 붙이지 않는다.

## 식별자와 권한

- `owner_id` 같은 일반 식별자는 관계를 확인할 수 있도록 허용된 ERD 조회에서 실제 저장값을 표시한다. 일반 식별자를 모두 비밀값으로 취급해 일괄 마스킹하지 않는다.
- `[masked]` 같은 표시용 문자열을 DB에 저장하지 않는다. 마스킹이 필요하면 조회·표시 계층에서 처리한다.
- 비밀번호 해시, 토큰, API 키 등 비밀값은 별도로 최소한 보호하고 제외한 컬럼과 사유를 기록한다.
- ERD는 승인된 개발·관리 권한 범위에서 제공한다. 일반 식별자 원값 표시가 무인증 전체 DB 공개를 뜻하지 않는다.
- HR 익명화·소수 집계 차단과 역할별 과정 접근 범위는 업무 조회 및 화면의 권한 정책에서 지킨다. 원본 데이터 자체를 훼손하거나 다른 역할에 원값을 노출하지 않는다.

## 모든 테이블의 상호작용

- 상단 목록과 하단 다이어그램의 모든 테이블 박스에서 같은 실제 테이블 조회를 연다. 제목뿐 아니라 테이블 박스 전체를 클릭 가능하게 한다.
- 마우스 포인터와 하이라이트, 눈에 보이는 키보드 포커스를 제공한다. Tab 이동 후 Enter·Space로 연다.
- 인앱 모달에는 테이블명, 실제 컬럼과 행, 로딩·빈 상태·오류를 표시한다. Esc 닫기, 초점 가두기와 닫은 뒤 원래 테이블로 초점 복귀를 지원한다.
- Mermaid처럼 렌더링 후 SVG가 생성되는 경우 렌더 완료 후 실제 노드에 이벤트를 연결한다. 다시 렌더링해도 중복 연결이나 누락이 없어야 한다.
- 테이블 수를 고정 숫자로 가정하지 않고 스키마에서 도출한다. 모든 노드와 조회 대상 목록이 정확히 대응하는지 확인한다.

## 열람 경로와 재생성

- 서버 HTTP 페이지의 실제 DB 조회와 `file://` 문서의 동작을 구분한다. 파일을 직접 연 문서는 서버 인증·상대 API가 저절로 동작하지 않는다.
- 테이블 전용 조회 요구에서는 DB API에 연결된 서버 페이지를 제공한다. 파일 페이지가 API에 의존하면 접속 주소·인증·브라우저 제약을 명시하고 연결 불가 상태를 표시한다.
- 오프라인 내보내기를 별도 요청받았다면 정적 스냅샷이라는 사실과 생성 시점을 명시한다. 최신 DB 조회라고 안내하지 않는다. DB 전용 요구와 충돌하는 내장 데이터 경로를 임의로 만들지 않는다.
- 생성기의 입력 스키마, 실행 명령, 출력 파일, 실행 위치와 환경 주입 방법을 기록한다. 비밀값은 코드·생성 HTML·로그에 기록하지 않는다.
- 사용자가 여는 실제 파일 또는 HTTP 경로를 직접 검증한다. 다른 경로의 정상 결과로 완료를 대신하지 않는다.

## 인터랙티브 캔버스 ERD 뷰어

순수 바닐라 JS/CSS로 구현한 단일 파일 인터랙티브 ERD 뷰어 구조와 운영 규칙이다. React Flow 등 외부 라이브러리 없이 작동하며 오프라인 내보내기(`file://`)와 구조를 공유한다.

### 캔버스 구조

| 영역 | 내용 |
|---|---|
| **상단 툴바** | 도메인 선택 탭, 검색창 (테이블명 실시간 필터), 줌 컨트롤 (+/-/1:1/Fit), API 연결 상태 뱃지 |
| **좌측 사이드바** | 접이식 탐색기, 도메인 아코디언, 테이블 목록, 즉시 조회 버튼 (`.btn-sidebar-view[data-table]`) |
| **중앙 캔버스** | Pan/Zoom 단일 캔버스 (배율 0.25배-3.0배), 커서 중심 휠 줌, fitToView, 선택 테이블 PanTo + 하이라이트 펄스 |
| **FK 오버레이 뷰** | `#fk-overlay-view` — 전체 외래키 관계를 단일 오버레이로 표시 |

### 캔버스 선택 UX 규칙

테이블 선택 시 시각적 피드백은 **진입 펄스**와 **지속 선택 상태** 2계층으로 분리한다:

| 계층 | CSS 클래스 | 동작 | 지속 시간 |
|---|---|---|---|
| 진입 펄스 | `.table-highlight` | `@keyframes tableSelectPulse` — 주황 글로우 2회 반짝 | 약 1.3초 후 자동 제거 |
| 지속 선택 | `.table-selected` | 주황(`#ffa500`) 테두리 3.5px + `drop-shadow` 글로우 | 다른 테이블 선택 또는 빈 영역 클릭 시까지 유지 |

**구현 원칙**:
1. 하늘색(`#58a6ff`) 단독 하이라이트는 다크 배경에서 가독성이 낮으므로 선택 강조에 사용하지 않는다. **주황(`#ffa500`)** 이상의 고대비 색을 사용한다.
2. `resetTransform()` (1:1 버튼) 실행 시 `.table-selected` 요소가 있으면 scale 리셋 후 해당 요소를 뷰포트 중앙에 배치한다. 선택 없으면 기본 원점 복귀.
3. 캔버스 빈 영역 `mousedown` 시 `.table-selected`와 사이드바 `.selected`를 모두 해제한다.

### 생성 명령

생성기는 반드시 DB 환경 주입을 거쳐 실행한다. 단독 실행 시 SASL 인증 오류가 발생한다.

> [!IMPORTANT]
> ERD HTML 출력 파일은 빌드 산출물이다. UI 레이아웃, 스타일(CSS), 클라이언트 스크립트 수정 시 **반드시 생성기 원천 소스를 수정**한 후 재생성 명령을 실행해야 한다. 출력 파일을 직수정하면 차후 재생성 시 변경 사항이 완전히 덮어써진다.

```bash
# ERD HTML 재생성 (로컬 DB 환경 주입 필수)
node .bin/local-database.mjs pnpm exec tsx .bin/generate-erd-html.ts

# 오프라인 내보내기 (Mermaid SVG를 인라인으로 구워 file:// 에서도 동작)
pnpm exec node .bin/export-erd.cjs
# 출력: tmp/erd.html (정적 스냅샷 — API 실시간 조회 불가)
```

### 클릭 위임 주의사항

> [!CAUTION]
> `[data-table]` 전역 위임은 절대 사용하지 않는다. 사이드바 탐색기 아이템도 `data-table` 속성을 가지므로 전역 위임 시 사이드바 클릭이 모달을 열어 FK 조회 버튼을 클릭할 수 없게 된다.

```js
// 올바름 — Mermaid SVG 노드 + 샘플 버튼만 모달 트리거
e.target.closest('.mermaid svg [data-table], .btn-sample[data-table]')

// 금지 — 사이드바 아이템도 잡혀 FK 버튼 클릭 불가
// e.target.closest('[data-table]')
```

### Mermaid ER Comment Sanitization

DB 스키마의 필드 comment나 설명을 Mermaid ER 다이어그램의 `"..."` 표기에 삽입할 때, 다음 특수문자는 Mermaid 파서 구문 오류(Syntax error in text)를 일으키므로 반드시 제거(sanitize)한다:

| 문자 | 문제 |
|---|---|
| `"` | comment 구문의 닫는 따옴표로 오인식 |
| `[` `]` | Mermaid 구문 예약 문자 |
| `{` `}` | 엔티티 블록 경계로 오인식 |
| `(` `)` | 관계 라벨 구문 또는 수식과 충돌 |

```js
// 올바름 — 특수문자 제거 후 삽입
const cmt = comment
  ? ` "${comment.slice(0, 30).replace(/["\[\]{}()]/g, '')}"`
  : '';

// 금지 — 원본 comment 그대로 삽입
const cmt = comment ? ` "${comment.slice(0, 30)}"` : '';
```

### Mermaid SVG 텍스트 검증

Mermaid v11+에서 SVG 내 텍스트는 `<foreignObject>` 내 HTML 요소로 렌더링된다.

```js
// 올바른 셀렉터
'.domain-pane.active .mermaid svg foreignObject span'
'.domain-pane.active .mermaid svg foreignObject p'
'.domain-pane.active .mermaid svg foreignObject div'

// 잘못된 셀렉터 (항상 빈 결과)
'.domain-pane.active .mermaid svg text'
```

### 오프라인 내보내기 동작

1. Playwright로 ERD HTML을 로드하고 Mermaid 렌더링 완료 대기
2. 렌더링된 SVG를 인라인으로 구워 `module` 타입 스크립트 제거
3. `tmp/erd.html` 저장 → `file://`에서도 SVG 다이어그램 및 모달 정상 동작
4. 정적 스냅샷이므로 API 실시간 조회는 작동하지 않음

### 데이터 모달 테이블 수평 스크롤 패턴

컬럼이 많은 테이블 조회 시 셀 찌그러짐을 방지하고 수평 스크롤을 제공하기 위해 다음 레이아웃 규칙을 유지한다:

1. **Flex 높이 체인 유지**:
   - `.modal-body`: `display: flex; flex-direction: column; overflow: hidden;`
   - `.modal-tab-pane.active`: `display: flex; flex: 1; flex-direction: column; overflow: hidden;`
   - `.table-responsive`: `overflow-x: auto; overflow-y: auto; flex: 1;`
2. **테이블 및 셀 수평 확장 보장**:
   - `.data-table`: `width: max-content; min-width: 100%;` (부모 너비에 억지로 수축되지 않음)
   - `.data-table th, .data-table td`: `white-space: nowrap;` (필요 시 `max-width` 및 `text-overflow: ellipsis` 적용)

## 검증과 완료 보고

### 자동화 검증

프로젝트에 ERD 검증 스크립트가 있으면 로컬 파일 검증과 개발 서버 E2E 검증을 모두 실행한다. 주요 검증 항목: 사이드바 렌더링, 도메인 전환, 검색 필터링, 테이블 모달 열기/닫기, FK 오버레이 뷰, 줌 컨트롤, 폰트 크기(10px 이상), 오프라인 내보내기 동일 항목 통과.

### 수동 검증 체크리스트

1. 스키마와 다이어그램의 테이블·컬럼·관계 누락, `codes` 참조, 기본키 정책을 확인한다.
2. 런타임 정적 업무 데이터 import와 실패 시 대체 데이터가 없는지 검색한다. 시드 입력과 화면 조회 경로를 분리하여 검토한다.
3. 브라우저에서 모든 테이블의 마우스 클릭 및 키보드 열기, 초점 복귀, DB 값 일치, 빈 테이블, 조회 실패를 확인한다. 파일 경로가 요구되면 파일 경로도 별도 확인한다.
4. DB 전용 요구에서는 행 변경 후 재조회에 반영되는지 확인하여 오래된 내장 데이터가 아님을 검증한다. 승인 없이 검증용 운영 데이터를 변경하지 않는다.
5. 변경 범위에 맞는 타입·린트·회귀 검사를 실행한다. 정책 문서만 바꾼 경우 문서 구조·링크·필수 규칙의 정적 검사로 범위를 제한한다.
6. 결과에 이슈, 변경 파일, 실제 열람 링크, 재생성 명령, 실행한 검증과 남은 제한을 기록한다. DB 이관·화면 연결·ERD 개선 각각의 실제 완료 상태를 구분한다.
