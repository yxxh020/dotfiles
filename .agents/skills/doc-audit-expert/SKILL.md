> **[안내]** 이 파일은 각 프로젝트가 복사해갈 때 프로젝트 상황에 맞게 수정하여 사용하는 스킬 템플릿이다. 적용 시 이 안내 문구를 제거하고 프로젝트에 맞게 내용을 수정한다.

# 문서 감사 전문가 스킬

## 목적

모든 폴더의 문서 품질 이슈를 체계적으로 감사, 진단, 수리한다.
우선순위가 매겨진 발견 보고서를 생성한 뒤 문서별로 대상 수정을 적용한다.

---

## Phase 0 — 트리거 조건

사용자의 요청에 다음 신호가 포함되면 이 스킬을 활성화한다:
- "문서 리뷰", "문서 정리", "매뉴얼 정리", "docs 정리"
- "중복 충돌", "낡은 문서", "오래된 문서", "deprecated 문서"
- 사용자가 디렉터리를 가리키며 "리뷰" 또는 "정리"를 요청할 때

---

## Phase 1 — 범위 발견

1. **대상 범위 식별**: 사용자의 요청에서 대상을 파악한다.
   - 기본값: 프로젝트 루트의 `docs/` 디렉터리.
   - 사용자가 서브 프로젝트나 다른 폴더를 지정하면 해당 폴더로 범위를 제한한다.
   - 사용자가 명시적으로 파일을 나열하면 해당 파일만 감사한다.

2. **파일 인덱스 구축**: 대상 범위에서 `list_dir`을 재귀적으로 사용한다.
   파일 이름, 크기, 수정 타임스탬프를 기록한다.

3. **배포/운영 문서 클러스터 식별** — 겹칠 수 있는 파일 그룹:
   - 예시: `docker-build-manual.md` + `server-disk-cleanup-guide.md` + `checklist-live.md`
   - 예시: `handover-*.md` 파일들
   도메인 키워드(예: "deploy", "server", "disk", "ssh", "env")를 공유하는 파일을 그룹으로 묶는다.

---

## Phase 2 — 읽기 및 분석

범위 내 각 파일을 `view_file`로 읽는다:

### 2.1 자동 패턴 탐지

`grep_search`와 시각적 검사로 다음 안티패턴을 탐색한다:

| 코드 | 안티패턴 | 탐지 방법 |
|------|---------|----------|
| **C** 충돌 | 두 문서가 같은 주제에 대해 상반된 사실을 기술 | 파일 간 공유 키워드(명령어, 경로, 설정 값) grep 후 값 비교 |
| **D** 중복 | 동일하거나 거의 동일한 블록이 2개 이상 파일에 존재 | 고유 문구 grep; 파일 간 섹션 제목 비교 |
| **O** 구식 | 문서가 이후 교체된 도구, 경로, 프로세스를 참조 | 파일 날짜 vs 참조 날짜 확인; 폐기된 도구 이름 grep |
| **S** 구조 | 미해결 병합 충돌, 깨진 링크, 방치된 TODO, 남겨진 주석 코드 블록 | `<<<<<<<`, `>>>>>>>`, `[ ]` 체크박스, 데드 파일 링크 grep |

### 2.2 주요 grep 대상

```bash
# 병합 충돌 마커
grep -rn "<<<<<<< " docs/

# 오래된 인수인계 파일의 미해결 TODO 체크박스
grep -rn "- \[ \]" docs/handover-*.md docs/checklist-*.md

# 잠재적으로 낡은 도구 참조
grep -rn "pm2\|ecosystem.config\|pm2 reload" docs/

# 중복 cron 라인
grep -rn "docker.*prune" docs/

# 경로 불일치
grep -rn "/app/\|~/docs/\|~/staging/" docs/
```

### 2.3 모든 발견 사항 수집

각 발견 사항에 대해 기록한다:

```
[코드][ID] 짧은 제목
  파일 : file-a.md L12, file-b.md L45
  상세 : 충돌/중복/구식 콘텐츠가 무엇인지
  위험 : 심각 | 높음 | 보통 | 낮음
  조치 : 제안하는 수정 (한 문장)
```

## Phase 3 — 감사 보고서 생성

발견 사항을 아티팩트 `implementation_plan.md`에 다음 구조로 작성한다:

```markdown
# 문서 감사 보고서 — <범위> — <날짜>

## 요약
총 발견 건수: C=N D=N O=N S=N

## 🔴 충돌 (C)
...

## 🟡 중복 (D)
...

## 🔵 구식 (O)
...

## ⚠️ 구조적 (S)
...

## 개선 계획 (우선순위 순)
| 우선순위 | ID | 조치 | 영향 파일 |
|---------|-----|------|----------|
...
```

심각도 기준 우선순위 순서:
1. **S** 항목 (구조/병합 충돌) — 항상 최우선, 도구를 깨뜨림
2. **C** 항목 — 상충 명령을 따를 경우 운영 위험
3. **O** 항목 — 개발자의 인지 부담
4. **D** 항목 — 유지보수 부담

보고서를 사용자에게 제시하고 **변경 전에 반드시 승인을 기다린다**.

---

## Phase 4 — 수정 실행 (사용자 승인 후)

우선순위 순서대로 발견 사항을 처리한다. 각 수정에 대해:

### 4.1 충돌 (C) 수정
- **권위 있는 소스**를 판별한다 (더 최근 날짜, 더 높은 SSOT 등급, 또는 사용자 확인).
- 비권위 파일을 맞추어 업데이트하거나 `> [!NOTE] 정본은 [권위 파일]을 참고한다.` 콜아웃을 추가한다.
- 콘텐츠를 조용히 삭제하지 않는다 — 폐기된 섹션은 `> [!WARNING] <날짜> 기준 폐기됨`으로 감싼다.

### 4.2 중복 (D) 수정
- 해당 콘텐츠 블록의 **단일 진실 공급원(SSOT)**으로 하나의 파일을 지정한다.
- 다른 파일의 중복 블록을 교차 참조로 교체한다:
  ```markdown
  > 전체 내용은 [정본 문서 제목](상대경로/파일.md)을 참고한다.
  ```
- 두 파일이 문자 단위로 동일하고 사용자가 확인한 경우에만 콘텐츠를 삭제한다.

### 4.3 구식 (O) 수정
- 섹션이 완전히 대체된 경우 헤더를 추가한다:
  ```markdown
  > [!WARNING]
  > **폐기됨** — 이 섹션은 현재 사용하지 않는 배포 방식을 설명한다.
  > 현재 절차는 [docker-build-manual.md]를 참고한다.
  ```
- 업데이트 가능하면 현재 상태를 반영하여 다시 작성한다.
- 파일 전체가 대체된 경우 상단에 `DEPRECATED` 배너를 추가하고 파일은 유지한다 (삭제하지 않음 — 이력 참조 가치).

### 4.4 구조적 (S) 수정
- **병합 충돌**: 올바른 쪽을 선택하여 해결한다. 비자명한 경우 해결 블록 위에 결정 사유를 주석으로 남긴다.
- **방치된 체크박스**: `[x]` (완료) 또는 `[~]` (취소/더 이상 해당 없음)로 표시하고 메모를 남긴다.
- **깨진 링크**: 올바른 경로로 업데이트하거나 링크를 제거한다.

### 4.5 각 파일 편집 후
- 빠른 자체 검토: 편집된 섹션을 다시 읽어 새로운 불일치가 발생하지 않았는지 확인한다.
- 작업 추적기(`task.md`)에 변경 사항을 기록한다.

---

## Phase 5 — 커밋

모든 수정 적용 후:

1. 수정된 문서 파일만 명시적으로 스테이징한다:
   ```bash
   git add docs/<파일1>.md docs/<파일2>.md ...
   ```
2. 프로젝트 컨벤션에 따라 커밋한다:
   ```
   docs: #<이슈번호> 배포 매뉴얼 감사 및 정리
   ```
   이슈가 없으면 `github-issue` 스킬로 먼저 생성한다.

3. 최종 변경 요약을 사용자에게 제시한다.

---

## Phase 6 — 선택사항: 후속 작업 기록

감사 결과 문서 편집이 아닌 코드나 인프라 변경이 필요한 구조적 이슈가 발견되면, GitHub 이슈나 작업 문서에 새 섹션으로 기록한다:

```markdown
## 📋 문서 감사 후속 작업 — <날짜>
- [ ] <작업 설명> (문서 감사 중 발견됨, 아직 미해결)
```

---

## 제약 사항 및 규칙

- 사용자의 명시적 확인 없이 **파일 전체를 삭제하지 않는다** — 대신 폐기 배너를 사용한다.
- 두 소스가 모두 신뢰할 수 있는 경우 가정만으로 "권위 소스"를 **조용히 덮어쓰지 않는다** — 사용자에게 확인한다.
- **한 번에 한 파일씩** — 단일 도구 호출에 여러 파일을 일괄 편집하지 않는다; 속도보다 정확성이 중요하다.
- 수정 대상이 아닌 **기존 주석과 제목을 모두 보존**한다.
- 사용자가 전체 변경 이력을 검토할 수 있도록 **모든 편집을 작업 추적기 아티팩트에 기록**한다.
