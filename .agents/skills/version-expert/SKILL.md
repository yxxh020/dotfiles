# 버전 관리 전문가 스킬 (Version Management Expert)

이 스킬은 프로젝트의 버전을 올리고(bump), 변경사항을 커밋하고, 지정된 버전으로 Git 태그를 생성하는 작업을 자동화합니다.

사용자가 "버전 올리자", "버전 업데이트 해줘", "버전 스킬 실행해줘" 등의 요청을 할 때 이 스킬을 적용합니다.

---

## 1. 버전 식별 및 업데이트 규칙

1. **현재 버전 확인**:
   - 프로젝트의 버전 관리 파일에서 현재 버전을 확인합니다:
     - **Node.js**: `package.json`의 `"version"` 필드
     - **Python**: `pyproject.toml`의 `[project] version` 또는 `setup.cfg`
     - **기타**: 프로젝트 루트의 `VERSION` 파일 또는 설정 파일
   - `git describe --tags --abbrev=0` 또는 `git tag -l` 명령으로 가장 최근에 생성된 Git 태그를 대조 확인합니다.
2. **새 버전 결정**:
   - 사용자가 명시한 버전(예: "1.8.0으로 설정해줘")이 있다면 해당 버전을 사용합니다.
   - 명시하지 않은 경우 기본적으로 패치(Patch) 버전을 1 올립니다 (예: `1.8.0` -> `1.8.1`).
   - 메이저(Major) 또는 마이너(Minor) 버전 변경 여부는 사용자의 확인을 거칩니다.

---

## 2. 버전 반영 절차

1. **단일 진실 원천 (SSOT)**:
   - 프로젝트의 주 버전 관리 파일을 새 버전으로 수정합니다.

2. **자동 동기화 확인**:
   - 버전이 빌드 시스템이나 환경변수를 통해 자동 주입되는 파이프라인이 있는지 확인합니다.
   - UI에 버전이 표시되는 위치가 있다면 해당 컴포넌트도 함께 업데이트합니다.

3. **모노레포 처리**:
   - 모노레포의 경우 관련 패키지들의 `package.json` 버전을 동일하게 맞춥니다.

---

## 3. 커밋 및 Git 태그 생성

1. **커밋 생성**:
   - 버전 관련 변경 파일만을 스테이징합니다.
   - 프로젝트 커밋 규칙에 따라 커밋 메시지를 작성합니다:
     ```bash
     git add <버전 관련 파일들>
     git commit -m $'chore: bump version to {새 버전}\n버전 {새 버전}으로 변경'
     ```
2. **Git 태그 생성**:
   - **태그는 배포 브랜치(dev, release 등)에서만 생성합니다.**
   - `main` 브랜치는 병합 시 태그가 가리키는 커밋을 상속받으므로, main에서 별도로 태그를 생성하지 않습니다.
   - 커밋 후 해당 커밋에 동일한 버전명으로 Git 태그를 생성합니다:
     ```bash
     git tag -a v{새 버전} -m "v{새 버전} 릴리스"
     ```
3. **태그 푸시**:
   - 브랜치 푸시 시 버전 태그도 원격 저장소에 함께 푸시합니다:
     ```bash
     git push origin <브랜치> --tags
     ```
4. **완료 보고**:
   - 이전 버전과 새 버전명, 적용된 커밋 메시지, 생성 및 푸시 대상 태그 이름을 요약하여 사용자에게 보고합니다.

---

### ⛔ 독단적 결정 금지 (Do NOT Decide Alone)
- 사용자 확인 없이 `main` 브랜치에 직접 푸시하거나 태그 생성 금지
- **`main` 브랜치에서 태그를 별도 생성하지 않음** — 배포 브랜치의 태그를 병합 시 그대로 계승
- 원격 푸시(`git push`) 시 버전 태그를 누락하지 않고 반드시 함께 전송
- 명시적인 지시 없이 메이저(Major) 버전을 올리는 행위 금지
