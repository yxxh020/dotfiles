# 프로젝트 언어 및 문서 관리 정책 스킬 (language-policy)

이 스킬은 프로젝트 진행 시 작업자(AI 및 인간)의 주 사용언어를 존중하고 동시에 문서 작성의 효율성과 일관성을 유지하기 위한 언어 정책을 다룹니다.

## 1. 기본 원칙 (Default: Korean Only)
* **기본 한국어 작성 원칙**: 별도의 명시적 요청이 없는 한 **앞으로 생성·작성하는 모든 문서(docs, markdown, plans, PRD, todo, test 등)**, 대화, 제안, 커밋 메시지, GitHub 이슈는 **항상 한국어 단독(Korean Only)**으로 작성한다.
* **명시적 요청 시에만 한영 병용**: 사용자가 "한영 병기", "한/영 병용", "bilingual" 등을 **명시적으로 요청한 경우에만** 한국어와 영어를 병용하여 작성한다.

## 2. 세부 적용 기준

| 대상 분류 | 적용 언어 | 상세 내용 및 기준 |
| :--- | :--- | :--- |
| **생성 문서 (docs, plans, markdown 등)** | **한국어 단독 (Korean Only)** | 별도 요청이 없으면 모든 생성 문서는 한국어만 사용 |
| **작업 계획 및 이슈 (계획 문서, GitHub 이슈)** | **한국어 단독 (Korean Only)** | 기본적으로 한국어로 작성 (별도 요청 시에만 한영 병기) |
| **대화 및 피드백** | **사용자 주 언어 (한국어)** | 사용자의 프롬프트 언어로 답변 |
| **명시적 다국어 요청 시** | **한영/다국어 병용 (Bilingual)** | 사용자가 명시적으로 요청한 경우에 한하여 1:1 병기 |
| **웹 서비스 UI / i18n 사전** | **다국어 지원 (ko, en, vi 등)** | 실제 서비스되는 웹 UI 다국어 사전 파일(`messages/*.json`) |

## 3. 다국어 병용 요청 시 작성 형식 (Bilingual Format - 명시적 요청 시에만 적용)

사용자가 다국어 병용을 명시적으로 요청했을 때만 아래 형식을 준수합니다:

1. **언어 태그 접두사 금지**: `[KO]`, `[EN]` 등의 인위적인 언어 태그 접두사를 사용하지 않고 자연스러운 배치로 구분한다.
2. **제목 형식**: `한국어 제목 / English Title`
3. **본문 배치**: 한국어 문장 바로 아래에 이탤릭체(`*...*`) 또는 들여쓰기로 영어 번역을 1:1 배치한다.
4. **목록 세부 항목(Bullet Points) 1:1 병기**: 주요 작업 및 하위 목록 작성 시 누락 없이 1:1로 번역을 병기한다.
5. **표(Tables)**: 셀 내에서 `<br/>` 태그를 사용하여 한국어와 영어를 구분한다.
