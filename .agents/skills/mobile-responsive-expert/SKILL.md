# 모바일 반응형 디자인 전문가 (Mobile Responsive Expert)

이 스킬은 웹 애플리케이션의 모바일 웹 뷰포트 지원을 극대화하고, 모바일 환경에 적합한 UI/UX 표준을 수립하여 렌더링 깨짐 현상을 방지하는 것을 목표로 한다.

## 트리거 조건
- 모바일 뷰포트 및 반응형 레이아웃 버그를 수정할 때
- GNB(Global Navigation Bar)의 모바일 햄버거 메뉴나 반응형 내비게이션을 구현할 때
- 모바일 해상도에서 터치 영역, 폰트 크기, 스크롤 영역을 최적화할 때

## 모바일 최적화 구현 가이드라인

### 1. 반응형 GNB 및 모바일 내비게이션
- **햄버거 메뉴 도입**: 데스크톱의 가로형 메뉴는 모바일(너비 640px 미만)에서 숨기고, 햄버거 버튼(`☰`)을 누르면 나타나는 반응형 드롭다운/사이드바 메뉴로 대체한다.
- **터치 영역 보장**: 모든 인터랙티브 요소(링크, 버튼, 드롭다운 항목 등)는 최소 **48x48px** 이상의 터치 영역(Padding 포함)을 확보하여 오작동을 방지한다.

### 2. 데스크톱 전용 요소의 제어
- **단축키 표시 제어**: 물리 키보드가 없는 모바일 환경에서는 단축키 안내 배너 또는 단축키 가이드 UI 컴포넌트가 불필요한 노이즈가 될 수 있다. 따라서 모바일 화면에서는 `hidden md:flex` 또는 `hidden sm:block` 등 반응형 숨김 클래스를 사용해 데스크톱 전용 기능 및 단축키 안내 팁을 명시적으로 숨김 처리한다.

### 3. 반응형 레이아웃 및 스크롤 방지
- **Viewport Overflow 방지**: 뷰포트 너비를 넘어서서 가로 스크롤(`overflow-x-auto`가 의도되지 않은 영역)이 발생하는 현상을 방지한다. 레이아웃 컨테이너에는 `w-full` 및 `max-w-screen` 등을 적절하게 사용한다.
- **반응형 접두사**: 반응형 분기(`sm:`, `md:`, `lg:`)를 활용하여 점진적으로 레이아웃을 확장하며, 항상 모바일 우선(Mobile-First) 디자인 원칙에 입각하여 기본 클래스를 작성한다.

## 출력 형식 및 검증
- 수정된 반응형 레이아웃이 포함된 컴포넌트는 Chrome DevTools 모바일 에뮬레이터(390px, 768px 등)를 통해 렌더링에 이상이 없는지 확인해야 한다.
- 모바일 브라우저 환경에서 단축키 오버레이가 불필요하게 켜지거나 헤더 메뉴가 겹치는 현상이 완전히 해결되었음을 확인한 후 완료 보고를 작성한다.
