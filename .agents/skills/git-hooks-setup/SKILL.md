# Git Hooks 설정 스킬

이 스킬은 프로젝트 내의 Git Hook 설정을 자동화하고, 모든 기여자가 일관된 Git 커밋 메시지 규칙을 준수하도록 강제하는 도구를 제공한다.

## 1. 사전 확인

* 프로젝트 루트에 `.git/` 디렉터리가 존재해야 한다.
* 이 스킬에서 제공하는 스크립트는 POSIX 호환 셸(Bash, Zsh 등) 환경을 기준으로 작성되었다.

## 2. 구성 파일 설명

이 스킬은 `scripts/` 디렉터리 하위에 다음 두 개의 핵심 파일을 포함한다.

* **`setup.sh`**: 로컬 `.git/hooks/` 디렉터리로 훅 파일을 복사하고 실행 권한(`chmod +x`)을 자동으로 부여하는 셋업 스크립트이다.
* **`commit-msg`**: 커밋 시점에 실행되어 메시지가 정해진 정규식 패턴(접두어 + 이슈번호)을 준수하는지 검사하는 실제 Git Hook 스크립트이다.

## 3. 적용 방법 (설치 절차)

이 스킬을 프로젝트에 이관하여 적용하려면 다음 단계를 따른다.

1. **디렉터리 생성 및 파일 복사**:
   * 이 스킬 폴더 전체를 프로젝트의 `.agents/skills/git-hooks-setup/` 위치로 복사한다.
   * 또는, 실행 스크립트(`setup.sh`, `commit-msg`)를 프로젝트의 셸 도구 모음 폴더(예: `.bin/` 또는 `scripts/`)로 옮긴다.

2. **설정 실행**:
   * 프로젝트 루트 또는 스크립트가 위치한 폴더에서 아래 명령어를 실행하여 훅을 등록한다:
     ```bash
     bash setup.sh
     ```

3. **작동 확인**:
   * 규격에 맞지 않는 커밋 메시지로 커밋을 시도하여 훅이 정상적으로 동작하고 차단하는지 검증한다.

## 4. 커밋 메시지 규칙 정의

기본 제공되는 `commit-msg` 훅은 다음과 같은 커밋 컨벤션을 강제한다. (프로젝트별 규칙에 맞게 `commit-msg` 내의 정규식을 수정하여 사용한다.)

* **기본 형식**: `<접두어>: #<이슈번호> <설명>`
* **허용되는 접두어**: `feat`, `fix`, `refactor`, `style`, `test`, `chore`, `docs`, `perf`, `ci`
* **올바른 예시**:
  * `feat: #101 사용자 로그인 기능 추가`
  * `fix: #204 로그인 페이지 UI 리렌더링 버그 수정`
* **이슈번호 생략 가능 케이스**:
  * `chore`, `docs` 등으로 시작하는 가벼운 변경 사항은 프로젝트 설정에 따라 이슈번호 없이 커밋이 허용된다 (예: `chore: 패키지 의존성 업데이트`).

## 5. 예외 상황 처리 및 문제 해결

* **권한 에러(Permission Denied)**:
  * 훅 실행 권한이 누락된 경우 발생한다. `chmod +x .git/hooks/commit-msg` 명령을 실행하여 권한을 수동으로 보완한다.
* **훅 우회 (권장하지 않음)**:
  * 긴급한 상황에서 일시적으로 훅 검사를 건너뛰어야 할 경우, 커밋 명령 뒤에 `--no-verify` 플래그를 붙여 실행한다 (예: `git commit -m "임시 저장" --no-verify`).
