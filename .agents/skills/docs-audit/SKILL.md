# Docs Audit & Optimization Skill (문서 감사 및 최적화)

이 스킬은 프로젝트 문서가 **오직 프로젝트의 현재 상태**만을 정확하게 나타내도록 보장하고 관리하는 역할을 수행합니다.

## 🎯 목표 (Goal)

```
❌ 과거 이력 (Past History)      →  ✅ 현재 상태 (Current State)
❌ 중복된 내용 (Duplicate)       →  ✅ 단일 진실 공급원 (SSOT)
❌ 과정 및 단계 (Process/Steps)  →  ✅ 최종 결과 및 결정 사항 (Result/Decisions)
❌ 모호성 (Ambiguity)            →  ✅ 명확성 (Clarity)
```

---

## 📖 핵심 원칙 (Core Principles)

### 1. 현재 상태만 반영 (Represent the Current State Only)
- **과거 변경 사항**: Git 로그에 위임합니다 (상세한 커밋 메시지로 충분합니다).
- **프로세스 세부 사항**: 코드 및 인라인 주석에 위임합니다.
- **이력 검증**: 필요한 경우 `git log --oneline` 등을 통해 확인하며, 문서 파일 내에 이력을 누적하지 않습니다.

### 2. 문서 볼륨 최소화 (Minimize Documentation Volume)
- **중복 제거**: 동일한 정보가 프로젝트 내 두 군데 이상 존재하지 않도록 합니다.
- **불필요한 메타데이터 제거**: 마크다운 파일 내에서 "최종 수정일", "버전 로그" 등의 불필요한 메타데이터 줄을 제거합니다.
- **역할 분리**: 각 문서의 대상 독자와 역할을 명확히 구분하여 관리합니다.

### 3. 명확한 역할 정의 (Clear Role Separation)
| 문서 | 대상 독자 | 내용 초점 |
|---|---|---|
| **README.md** | 사용자 / 외부 개발자 | 설치, 실행 방법, 현재 제공되는 기능 및 프로젝트 현황 |
| **AGENTS.md** | 개발 에이전트 / 기획자 | 핵심 요구사항 명세(SSOT), 개발 규칙, 아키텍처 원칙, 작업 체크리스트 |
| **코드 주석** | 구현자 | 이슈 번호 참조, 구체적인 코드 레벨의 구현 결정 사항 |
| **git log** | 변경 사항 조사자 | 히스토리 변경 맥락, 버그 수정 내용, 증분 진화 이력 |

## 🔍 감사 및 정리 프로세스 (Audit & Clean Process)

### 1단계: 스캔 및 현황 파악 (Read Phase)
프로젝트 내 문서와 현재 상태를 조회하기 위해 터미널 명령어를 사용합니다:
```bash
# 코드 상태 확인
git log --oneline -10          # 최근 커밋 이력
git status                      # 작업 트리 상태
```

**수집 및 기록 항목:**
- 활성 개발 단계 (예: 완료됨, 진행 중, 계획됨)
- 테스트 상태 (성공/실패 수)
- 열려 있거나 닫힌 이슈 및 PR 정보

### 2단계: 모순 및 중복 분석 (Analyze Phase)
주요 파일들 간에 중복되거나 모순되는 정보가 있는지 분석합니다:
- **README.md**: 현재 개발 단계, 주요 기능, 로컬 실행 방법만 유지하고 과거 릴리즈 노트는 제거합니다.
- **AGENTS.md**: 활성화된 개발 규칙과 체크리스트만 남기고, 구식 설계 근거나 과거 로그는 제거합니다.
- **코드 주석**: 특정 우회 코드(Workaround)나 로직이 왜 존재하는지 설명하기 위해 이슈 번호(`#N`)를 주석으로 명시합니다.

**검사 체크리스트:**
- [ ] 과거 이력이나 프로세스 단계를 설명하는 섹션이 존재하는가?
- [ ] 중복된 메타데이터(날짜, 작성자)가 있는가?
- [ ] 여러 파일에 걸쳐 동일한 정보가 중복 정의되어 있는가?
- [ ] Git 로그나 코드 자체에서 직접 유추할 수 있는 정보인가?

### 3단계: 정리 (Clean Phase)
분석 결과를 바탕으로 불필요한 콘텐츠를 과감히 삭제하거나 참조로 대체합니다:
- **삭제 대상**:
  - 과거 버그 수정 목록 (Git 로그와 중복)
  - 구식 설정 파일 설치 단계
  - 이미 완료된 작업의 내부 세부 진행 이력
- **유지 / 추출 대상**:
  - 현재 상태 정보 (예: MVP 1단계 완료)
  - 개발 워크플로우 컨벤션 및 사전 검증 규칙

만약 문서 파일 전체의 사용을 중단해야 할 경우, 파일 삭제 전에 최상단에 감쇠(Deprecation) 경고를 추가하고 사용자에게 확인을 요청합니다.

### 4단계: 최적화 수량화 (Measure Phase)
정리 작업 전후의 파일 라인 수 변화를 측정하여 기록합니다:
- **정리 전**: 수정 대상 파일의 전체 라인 수
- **정리 후**: 수정 대상 파일의 전체 라인 수
- **검증**: 필수적인 개발 지침이나 로컬 빌드에 필요한 설정 파라미터가 유실되지 않았는지 확인합니다.

### 5단계: 커밋 (Commit Phase)
프로젝트 표준 커밋 규칙에 맞춰 변경 사항을 커밋합니다. 커밋 메시지에 문서 정리 내용과 라인 수 감소율을 명확히 명시합니다.

## ⛔ 독단적 결정 금지 (Do NOT Decide Alone)
- 사용자 확인 없이 프로젝트 내의 특정 문서 파일 전체를 영구 삭제하는 행위
- 로컬 환경 구동이나 빌드 검증을 깨뜨릴 수 있는 설정 지침을 임의로 제거하는 행위
