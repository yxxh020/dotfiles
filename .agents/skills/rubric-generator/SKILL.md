# `rubric-generator` 스킬 지침서

이 스킬은 채점을 진행하거나 동료 상호평가(Peer Evaluation)를 준비할 때, 공정하고 객관적인 단답형 채점 기준표를 자동으로 설계해 준다.

## 언제 이 스킬을 호출하는가?

- 과제 지시사항이 완성된 후, 상호평가용 또는 채점용 루브릭을 생성할 때
- 주관적인 정성 평가 요소(디자인, 코드 퀄리티 등)를 배제하고 기계적으로 채점할 수 있는 명확한 지표가 필요할 때
- 생성된 루브릭을 바탕으로 `ai-grader` 스킬과 연계하여 과제 자동 채점 파이프라인을 구축하고자 할 때

## 작동 방식 및 행동 규칙

### 1. 기한 내 제출 기본 점수 할당

- 1번 항목은 무조건 "**기한 내 제출**"으로 고정한다.
- 기본 배점은 프로젝트에 맞게 조정한다 (예: 5점).

### 2. 1항목 1점 (Yes/No) 원칙

- 과제의 모든 달성 조건을 잘게 쪼개어 각각 1점짜리 문항으로 만든다.
- 하나의 문항 안에서 두 가지(A AND B) 이상을 섞어서 묻지 않는다.
  - ❌ "CSV 파일을 만들고 시각화도 하였는가?"
  - ✅ "CSV 파일을 만들었는가?" + "시각화를 하였는가?" (2개로 분리)
- 답변은 오직 **Yes(1점) / No(0점)**만 가능하도록 단순명료하게 질문 형태로 작성한다.

### 3. 문항 수 상한

- 채점 폼의 제출 제한에 따라 최대 문항 수를 설정한다 (기본값: 최대 9문항 이하 권장).
- 조건이 많을 경우 유사한 것을 통합하되, 통합 시 복합 조건이 되지 않도록 주의한다.

### 4. 객관성 (정성적 평가 배제)

- "코드가 우수한가?", "디자인이 예쁜가?" 등의 정성적 평가는 완전히 배제한다.
- 오직 지시사항의 조건이 물리적으로 "충족되었는가"만 묻는다.

## 결과 출력 포맷 예시

```markdown
| 번호 | 단답형 객관적 평가 기준 (Yes/No) | 배점 |
|:---:|:---|:---:|
| **1** | **기한 내 제출** / 과제를 기한 내에 지각하지 않고 제출하였습니까? | **5점** |
| **2** | 결과 파일을 정상적으로 생성하여 제출하였는가? | 1점 |
| **3** | 실습 코드가 에러 없이 정상적으로 실행되는가? | 1점 |
| **4** | 요구된 기능이 올바르게 구현되어 있는가? | 1점 |
```
