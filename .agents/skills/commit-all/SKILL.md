# 커밋 올(commit-all) 스킬

> **[안내]** 이 파일은 각 프로젝트가 복사해갈 때 프로젝트 상황에 맞게 수정하여 사용하는 템플릿이다.
> Pre-flight Checklist의 스펙 문서 경로와 검증 스크립트 경로는 프로젝트에 맞게 교체한다. 적용 시 이 안내 문구를 제거한다.

진행 중인 작업 완료 후 작업 트리가 clean 상태가 될 때까지 변경 사항들을 관련된 단위로 묶어 커밋한다.

## 핵심 커밋 규칙
- **커밋 메시지 형식**: [commit](../commit/SKILL.md) 스킬의 커밋 메시지 형식(`type: #이슈번호 설명`, 허용 타입, `chore` 및 `docs`의 이슈 번호 선택 규칙)을 그대로 따릅니다. 형식 규칙의 원본은 `commit` 스킬이며 이 문서에서 재정의하지 않는다.
- **Fast-Path (문서 및 경미한 변경 - 이슈 생략)**:
  - `docs`(문서/위키 작성·수정), `style`, 단순 `chore`(사소한 설정/패키지/정리)는 GitHub 이슈를 검색하거나 생성하지 않고 즉시 `<타입>: <설명>` 형식으로 커밋한다. (네트워크 지연 및 불필요한 이슈 남발 방지)
- **Normal-Path (실제 이슈 연동 필수 대상)**:
  - 기능 개발(`feat`), 버그 수정(`fix`), 아키텍처/스키마 변경 등 추적이 필요한 작업에만 이슈를 연결한다 (`type: #이슈번호 설명`).
  - **이슈 검색 제한**: 열린 이슈 확인은 `gh issue list --state open --limit 10` 1회로 한정한다. 키워드 검색(`--search`)을 여러 번 반복하는 탐색 낭비를 절대 금지한다. 열린 목록에 없으면 즉시 `gh issue create` 1회로 생성하거나 기존 관련 이슈 번호를 사용한다. 임의의 가짜 번호 기재는 절대 금지된다.
- **히스토리 보존**: 과거의 작업 맥락을 커밋 메시지 본문에 상세히 기록한다. (TODO·테스트 계획 등 일회성 작업 문서는 작업이 완료된 상태를 **먼저 코드와 함께 커밋하여 Git 히스토리에 완전히 남긴 후**, 이어지는 정리 커밋에서 삭제해야 한다. 완료 내용을 커밋하기도 전에 미리 삭제하면 히스토리에 남지 않으므로 절대 금지한다.)
- **커밋 후 Push 금지**: 로컬에서 커밋까지만 수행하며, 절대 `git push`를 수행하지 않는다.
- **불필요한 파일 무시**: 커밋 대상이 아닌 파일(`.env`, 빌드 결과물 등)은 억지로 묶지 말고 `.gitignore`에 추가한다.

## 🛑 커밋 전 자체 검증 (Pre-flight Checklist)
커밋 명령을 수행하기 전에, 반드시 아래 항목들을 스스로 점검(Self-review)하고 통과(Pass)했을 때만 커밋을 진행하십시오. 하나라도 누락되면 커밋을 중단하고 부족한 작업을 먼저 수행하십시오.

1. **SSOT 점검:** 수정한 코드가 프로젝트의 목표 스펙 문서(PRD 등)를 완전히 충족했는가?
2. **Security Gate:** 커밋할 코드에 악의적인 난독화(Obfuscation) 코드나 의심스러운 시스템 명령어(예: `eval base64`, `exec /dev/tcp` 등) 주입이 없는지 확인했는가?
3. **Harness Gate:** 쉘 스크립트(`.sh`) 등을 수정했고 프로젝트에 검증 스크립트가 있다면 실행하여 문법/규칙 및 보안 오류가 없음을 터미널 출력으로 확인했는가?
4. **Screenshot Gate:** 최종 결과물이 정상 동작함을 증명할 수 있는 브라우저 캡처나 명령어 성공 화면(스크린샷 증명)을 확보했는가?
5. **Version & Tag Gate (전면 비활성화 - 상시 질문 금지):** 버전 체크 및 버전 업 질문은 완전히 중지(OFF) 상태입니다. 커밋 시 버전에 대해 일체 확인하거나 묻지 않고 항상 즉시 통과(Pass)합니다. (오직 사용자가 명시적으로 "버전 올려줘"라고 지시한 경우에만 수동 처리)

## 🛠️ 작업 트리 완전 정리 절차 (Workflow)
"남은 거 다 커밋해줘"와 같이 전체 정리를 요청받은 경우 아래 절차를 따릅니다.

1. `git status`로 수정된 파일과 추적되지 않는 파일을 모두 확인한다.
2. 모든 변경 사항을 논리 그룹으로 분류한다 (예: `[feature/api]`, `[ui/component]`, `[docs/planning]`, `[tests]`, `[config/deps]`).
   - **(선택적) Jev 기반 논리 그룹 분류**: 파일 수가 많거나 성격이 모호할 때 `jev`를 활용해 고속 분류할 수 있다 (`command -v jev` 확인 시).
     ```bash
     GROUP=$(echo "$FILE_PATH" | jev -c "api,ui,docs,config,tests" -q)
     ```
3. 그룹별로 하나씩 커밋한다 (타입 판정 및 메시지 형식 검증은 [commit](../commit/SKILL.md)의 Jev 파이프라인 활용).
4. 각 커밋 후 `git status`로 남은 파일을 확인한다.
5. 작업 트리가 깨끗해질 때까지 반복한다.

> **Jev Graceful Fallback**: `jev` 도구가 없거나 환경변수/Keyring이 미설정된 환경에서는 에러 없이 기본 수동/규칙 기반 그룹화 절차로 자동 fallback된다.

## 🏷️ 버전 업(Bump) 및 Git 태그 생성 연동 절차 (Version Bump & Tagging)

> **🛑 상시 질문 전면 중지 (100% 수동 요청 시에만 실행)**: 버전 체크 및 질문은 상시 비활성화되어 있습니다. 커밋이나 작업 완료 시 버전 관련 질문이나 제안을 절대 하지 않습니다. 오직 사용자가 채팅창에서 직접 **"버전 올려줘"**, **"patch 버전 업"**, **"vX.Y.Z로 올려줘"**라고 명시적으로 지시한 경우에만 아래 절차를 수행합니다.

사용자가 명시적으로 버전 업데이트를 지시한 경우, **절대로 Git 태그 생성을 누락해서는 안 되며** 아래 순서대로 수행한다:

1. **일반 변경사항 우선 완결**:
   - 버전 파일(`package.json` 등)을 제외한 일반 코드/문서 변경사항들을 먼저 위 절차에 따라 논리 단위별로 커밋하여 작업 트리를 clean 상태로 만든다.
2. **새 버전 산정 및 파일 수정**:
   - `frontend/package.json` (또는 루트 `package.json`)의 현재 버전을 확인한다.
   - 요청에 따라 버전을 올린다 (예: patch 요청 시 `0.5.0` ➔ `0.5.1`).
   - 버전이 명시된 파일(`package.json`)의 `"version"` 필드를 새 버전으로 수정한다.
3. **버전 bump 독립 커밋 생성**:
   - 버전 관련 파일만 스테이징(`git add`)하고 별도의 릴리즈 커밋을 생성한다 (한글 설명 필수):
     ```bash
     git commit -m "chore: v0.5.1 버전 업데이트 (bump version)"
     ```
4. **Git 태그(Annotated Tag) 생성 필수 (절대 누락 금지)**:
   - 커밋 완료 즉시 해당 커밋에 반드시 주석 달린 Git 태그(Annotated Tag)를 생성한다:
     ```bash
     git tag -a v0.5.1 -m "Release v0.5.1"
     ```
5. **태그 생성 검증 및 보고**:
   - `git tag -l "v0.5.1"` 또는 `git describe --tags`로 태그 생성을 터미널에서 직접 검증한다.
   - 사용자 완료 보고 시 **생성된 새 버전과 Git 태그명(`v0.5.1`)을 반드시 명시**한다.

**완료 확인 명령어:**
```bash
git status              # "nothing to commit, working tree clean" 확인
git log --oneline -10   # 커밋 이력 검토
git describe --tags     # 최신 Git 태그 확인
```

## 커밋 메시지 예시

```
feat: #77 새로운 로그인 모달 구현
fix: #57 JWT 만료 갱신 루프 수정
refactor: #88 임시 계획 문서 정리 및 삭제
chore: 테스트를 위한 패키지 의존성 업데이트
chore: v0.5.1 버전 업데이트 (bump version)
```
