# 스킬 추가 전문가

사용자가 원하는 기능을 파악하여 AI 에이전트가 즉시 사용할 수 있는 스킬(`SKILL.md` 및 보조 파일)을 생성하고 등록한다.

## 스킬 구조 규칙

```
.agents/skills/<skill-name>/
├── SKILL.md              ← 필수: 스킬 정의
├── scripts/              ← 선택: 실행 스크립트
└── references/           ← 선택: 참조 문서
```

## SKILL.md 작성 규칙

1. **YAML frontmatter** (필수):
   - `name`: 영어 kebab-case (예: `log-analyzer`)
   - `description`: 한 문장으로 이 스킬이 무엇을 하는지 설명
2. **본문 구성**:
   - 이 스킬을 언제 호출해야 하는지 (트리거 조건)
   - 어떤 명령어를 내부적으로 사용하는지 (실행 규칙)
   - 어떤 결과를 사용자에게 반환하는지 (출력 형식)

## 스킬 설계 시 핵심 원칙 (Engineering Principles)

1. **DRY (중복 방지)**:
   - 새로운 스킬을 설계하기 전에, 현재 인벤토리에 등록되어 있는 스킬 목록을 반드시 확인합니다. 이미 유사한 역할을 수행하는 스킬이 있다면 신규 스킬을 생성하지 말고 기존 스킬을 개선하여 중복을 예방해야 합니다.
2. **KISS (단순성 유지)**:
   - 스킬 가이드는 최대한 단순하고 핵심적인 동작 지침만 포함해야 합니다. 불필요하게 정교한 다중 분기 시나리오나 복잡한 셸 스크립트를 작성하기보다, 에이전트가 마크다운 규칙 몇 줄로 직관적으로 이해하고 수행할 수 있도록 단순하게 설계합니다.
3. **SSOT (단일 진실 공급원)**:
   - 스킬 생성이 완료되면 반드시 `AGENTS.md` 파일의 **스킬 인벤토리** 한 곳에 해당 스킬명과 용도를 명확히 기록하여 전체 프로젝트에서 스킬 사용 규칙의 일관성이 유지되도록 해야 합니다.

## 스킬 등록 절차

1. **이름 선정**: kebab-case 영어명 (예: `docker-cleaner`)
2. **디렉터리 생성**: `.agents/skills/<name>/` 생성
3. **SKILL.md 작성**: 위 규칙 및 **설계 원칙**에 따라 작성
4. **스크립트 연결** (선택): `scripts/` 폴더에 실행 파일 생성, `chmod +x` 부여
5. **검증**: 마크다운 문법, 파일 권한 확인
6. **인벤토리 등록**: `AGENTS.md`의 스킬 인벤토리 테이블에 추가 (SSOT 원칙)
7. **보고**: 스킬 생성 완료를 사용자에게 보고
