# 사용자 테스트 안내 — 사용자 수동 검증 가이드 스킬

## 언제 이 스킬을 사용하는가

사용자가 최근 개발되거나 수정된 기능에 대해 수동 검증 단계를 요구하며 아래와 같이 질의할 때 이 스킬을 실행합니다:
- "테스트 해볼 방법?"
- "테스트?"
- "어떻게 테스트해?"
- "이 기능 어떻게 확인해?"

## 핵심 규칙

### 1. 클릭 가능한 마크다운 링크 제공
- URL 주소를 단순 텍스트(예: `http://localhost:3000/admin/...`)로 적지 않다.
- **반드시** 마크다운 링크 형식(예: `[데이터 등록 페이지](http://localhost:3000/admin/data-management/data-registration)`)으로 감싸서 제공한다.
- 사용자가 한 번의 클릭만으로 해당 테스트 화면으로 이동할 수 있도록 보장한다.

### 2. 환경별 URL 주소 결정
- 현재 대상이 되는 타겟 서버 환경에 맞게 도메인 주소를 제공합니다:
  - **로컬 개발 환경**: `http://localhost:3000` (또는 프로젝트에 설정된 로컬 포트)
  - **테스트/스테이징 서버**: 해당 프로젝트의 스테이징 URL (예: `https://staging.example.com`)
  - **운영 서버**: 해당 프로젝트의 실제 운영 도메인 (예: `https://example.com`)

### 3. 로케일 경로 준수
- 프로젝트에 다국어(internationalization) 처리가 되어 있다면, 현재 사용자의 로케일 설정에 맞는 정확한 경로 구조(예: `/kr/`, `/en/`)를 URL 경로에 포함해야 한다.

### 4. 구체적인 테스트 입력값 및 계정 정보 제공
- 링크 이동 안내와 함께, **반드시** 직접 입력하고 검증할 수 있는 실제 테스트용 데이터를 마크다운 표 형식으로 상세하게 제공한다.
- **핵심 사항**: 단순한 문장 설명이나 모호한 형식으로만 두지 말고, **실제로 즉시 작동 및 테스트가 가능한 구체적인 데이터(예: 제품 검색 테스트라면 3302 등 실제 테스트 가능한 제품 번호)**를 명시적으로 기입해야 한다.
- 제공해야 할 예시 데이터:
  - **테스트용 로그인 ID 및 비밀번호**: 검증 시 로그인이 필요한 경우 사용할 테스트 계정 정보
  - **검색 및 식별자 키**: 검색 필드나 폼에 입력할 대상 ID, 바코드 번호, 또는 키워드 예시
  - **입력 양식 데이터**: 복사해서 바로 붙여넣어 볼 수 있는 폼 필드별 값 예제

#### 예시 표 형식:
| 대상 작업 | 테스트 입력값 | 설명 / 기대 결과 |
|---|---|---|
| 관리자 로그인 | ID: `<admin-user>`<br/>PW: `<admin-password>` | 관리자 권한으로 로그인하여 검증 페이지에 접근한다. |
| 대상 레코드 식별자 | `3302` (실제 테스트 가능한 번호) | 상세 조회를 위해 검색창에 입력할 고유 ID이다. |
