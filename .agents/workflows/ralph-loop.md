# /ralph-loop 워크플로우

이 워크플로우는 이슈나 테스트 실패를 만났을 때, 에이전트가 단독으로 문제를 끝까지 디버깅하고 완벽히 통과할 때까지 자율 실행 루프를 구동한다.

## 실행 절차

1. **스킬 활성화**: `ralph-loop` 스킬의 6대 핵심 원칙과 반복 루프를 즉시 적용한다.
2. **실패 재현 및 원인 수집**:
   - 실패를 유발하는 명령(테스트, 빌드, 린트 등)을 직접 실행하여 정확한 로그와 에러 스택을 확보한다.
   - **(선택적) Jev 가설 검증**: 에러 로그를 기반으로 원인 가설을 0.1초 만에 확인한다.
     ```bash
     jev "$ERROR_LOG" -y "Is this error caused by <가설>?" -q
     ```
3. **가설 수립 및 외과적 수정**:
   - 한 번에 한 가지 가설만 세우고 최소한의 코드를 수정한다 (`karpathy-guidelines` 준수).
4. **실시간 브리핑 및 자동 진행 (Auto-Continue Gate)**:
   - ⚡ **수정 완료 즉시 사용자에게 아래 브리핑을 실시간 출력하고 멈추지 않고 계속 진행한다:**
     - 🔍 **감지된 오류 및 실패 원인** (실패 명령, 에러 스택 `파일:라인`)
     - 🛠 **가설 및 외과적 수정 조치** (가설 요약, 수정한 파일 및 변경 사항)
     - 💡 **원인 분석 및 설명** (발생 배경 해설, 적용한 해결 논리)
     - ⏩ **다음 단계** (동일 명령 재검증 자동 진행 안내)
   - ⚡ **브리핑 출력 직후, 사용자 입력을 기다리지 않고 즉시 동일 명령 재검증으로 자율 진행한다.**
5. **동일 명령 재검증 (Green Gate)**:
   - 수정한 후 동일한 명령을 재실행하여 문제가 해소되었는지 검증한다.
   - **(선택적) Jev 테스트 통과 판정**:
     ```bash
     IS_GREEN=$(echo "$TEST_OUTPUT" | jev -y "Did all tests strictly pass with zero failures or regressions?" -q)
     ```
   - 실패 시 다음 가설로 넘어가 루프를 반복한다 (4단계 브리핑 → 재검증 지속).
6. **완료 및 증거 제시**:
   - 모든 테스트가 통과(Green)하면 최종 실행 결과와 변경 내역을 `Done Report` 형식으로 요약 보고한다.
   - 외부 요인(권한, 토큰 등)으로 해결이 불가능한 경우에만 블로커를 명확히 정의하여 사용자에게 알린다.

> **Jev Graceful Fallback**: `jev` 명령어가 없는 환경에서는 표준 프로세스 종료 코드(`exit code 0`) 및 로그 직접 확인으로 자연스럽게 진행한다.
